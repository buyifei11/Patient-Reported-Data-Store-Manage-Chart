# Dataset roles

All reports are fictional and written in English. These files are for extraction development and evaluation, not model training or clinical validation.

The table below describes the **diagnostic extraction sets**. The separate
[`longitudinal/`](longitudinal/README.md) folder now supplies the working
four-week demo: 71 reports, three patients, 84 follow-up patient-days, and five
medication changes. It intentionally reuses the ten starter reports and adds
61 questionnaire-only submissions. Do not add the two dataset totals as if all
reports were independent. The offline demo itself does not create gold labels or
run the LLM for the questionnaire-only follow-up.

The separate [`text_pilot/`](text_pilot/README.md) now takes five of those existing
questionnaires as fact seeds, generates English feedback with one actual LLM
request, and provides reviewed references: five development reports, ten symptom
observations, and ten candidate-level checks. These are derived pilot examples,
not additional independent patients or test cases. Their
[first extraction baseline](../results/text-pilot-extraction/README.md) is now
recorded separately. They do not replace any historical set below or the current
dashboard inputs.

The separate [`text_validation/`](text_validation/README.md) contains ten newly
authored synthetic cases, 15 observations, and 15 candidate-level checks. It
extends the text pilot with varied sentence layouts and distinguishes zero,
unknown count, and unmentioned symptoms. The two extraction prompts were frozen
before generation. The [two-prompt comparison](../results/text-validation-comparison/README.md)
is now complete, using unchanged sources and references. These are targeted
validation cases, not a final independent clinical test. Further tuning based on
their results makes them development/regression material. The subsequent
[grouping experiment](../results/text-validation-grouping/README.md) now uses them
in that role: fragmentation decreased, but new errors reduced whole-report passes
from 8/10 to 7/10. A [compact grouping follow-up](../results/text-validation-compact/README.md)
returns to 8/10, with nausea duplicates still unresolved. Its saved-output diagnosis
traces a conservative daily-context merge gate; no runtime fix was applied during
that prompt comparison. A [two-stage follow-up](../results/text-validation-nausea/README.md)
then fixes Python and replays the saved candidates (10/10 correct normalized
reports). A separate prompt-only addition removes duplicates but introduces an
invalid quote (9/10 usable reports). The Python fix is retained; the new prompt
remains experimental. Sources and labels remain unchanged.

Each JSONL line is one report, not one observation. A report may describe multiple symptoms or no target symptoms. `report_id` joins a report to its reference record. Original IDs are R001-R010, additional development IDs are D001-D020, first held-out IDs are H001-H020, and fresh v3 validation IDs are T001-T020. Do not combine observation counts with report counts.

The prompt experiment uses the original and additional development sets together: 30 development reports, with 36 reference observations and 24 targeted checks. The held-out set remains separate. Running it twice does not turn 20 independent test cases into 40.

`cases.json` records each new report's scenario group, focus, and rationale. `review.md` records pre-inference review. Authors worked separately; labels were authored from the contract, not generated by the normalizer. A separate reviewer checked the held-out labels and cross-split narrative overlap, and two near-template narratives were rewritten before inference. These are agent-reviewed, AI-assisted synthetic references, not independent human clinical annotations.

Diagnostic data generation differs from the implemented four-week follow-up
dataset: most cases below are isolated edge cases. Longitudinal coverage and
correction-aware aggregation are exercised separately by the demo and its tests.

## Preserve the evaluation boundary

- Source text alone enters the LLM. Questionnaire answers and submission metadata are handled by code.
- Gold is used only for validation and scoring. It is never inserted into the extraction prompt.
- `observations` are final normalized references; they cannot directly train the text-only extractor. For example, a reconciled unknown count can originate from a clearly stated text count plus a conflicting questionnaire answer.
- `extraction_checks` inspect selected candidate fields before reconciliation. They are not a complete training dataset of candidate objects.
- No prompt or label changes are made in response to held-out outputs within the frozen experiment. Future tuning based on those errors turns these cases into known regression data; a later independent evaluation needs new cases.

The subsequent [normalization fix and offline replay](../docs/normalization_fix.md) use the observed H016 failure. Consequently, `heldout/` retains its historical name and frozen contents but is now known regression data for follow-up development, not a fresh independent test set.

The [v3 comparison](../docs/prompt_v3_experiment.md) uses all 50 older reports as known regression data and the separately authored 20 reports in `heldout_v3/` as fresh synthetic validation. The candidate prompt was locked before fresh-case inspection; manual review and label corrections occurred before any model inference. All 70 reports are run twice per prompt, but there are still only 70 unique reports. See `heldout_v3/review.md` for authorship, review, and limitations.

See [the frozen experiment protocol](../docs/prompt_experiment.md) for versions, run counts, controls, and interpretation.
