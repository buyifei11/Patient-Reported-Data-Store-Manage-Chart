# Scope and evidence prompt comparison: frozen protocol

Protocol date: 2026-11-15. This follow-up tests prompt engineering, not training.
The baseline is the current default v1; the candidate v3 includes v2's temporal
clarification plus changes to claim grouping, count scope, and evidence copying.
This comparison measures that complete prompt package; it does not isolate the
causal effect of each sentence or compare v3 directly against v2.

## Intervention and fixed components

`prompts/extraction_v3.txt` retains the candidate schema and field names. It
preserves a stated multi-episode count as one claim, distinguishes multi-day and
bounded-interval counts from daily totals, and prevents a bounded zero from
becoming whole-day absence. Date or location anchors alone do not make an event
a window. Earlier daily cumulative cutoffs remain explicit. Evidence must be a
literal contiguous span supporting all claimed fields, expanded across adjacent
sentences only when needed. `time_text` must be copied exactly inside the quote.
No labeled examples, case IDs, or reference answers are added to the prompt.

The model remains `gpt-5.4-mini-2026-03-17`. Both arms use the same current runtime,
including the midnight-to-submission normalization fix, strict schema, evaluator,
Responses API settings, reasoning effort `none`, and 2,048 output-token cap.
No deterministic repair, fuzzy evidence matching, extra model pass, automatic
retry, or schema change is included.

## Data and separation

The known regression split contains all 50 previously reviewed reports from
`data/raw`, `data/dev`, and `data/heldout`. These cases inform the prompt changes
and cannot establish performance on unseen examples.

The new validation split contains 20 reports T001-T020 in `data/heldout_v3`.
A separate author receives only the task contract and broad coverage objectives,
not the new prompt, old case texts, or historical model outputs. Gold is manually
authored from the contract and schema/provenance validated, not generated by the
normalizer. The candidate prompt is locked before the primary implementer reads
the new cases. A separate pre-inference review checks labels and narrative
overlap; label corrections are allowed before inference and documented. They
cannot be used to retune the locked candidate. Any discovered ambiguity after
inference is reported without silently changing labels or scores.

The locked v3 prompt SHA-256 before fresh-case inspection is
`6c0af35b5a22c10aeb020010830b7145b5dfd0063e058b81e52f805a2f4c096d`.

These are small AI-assisted synthetic sets with agent review, not independently
annotated patient data. Phenomena overlap by design, but exact text, identifiers,
and patient IDs must not cross splits; narrative overlap receives manual review.
Twenty deliberately challenging cases cannot estimate population accuracy.

## Execution and provenance

Run two paired rounds for both splits: 50 x 2 prompts x 2 rounds plus
20 x 2 prompts x 2 rounds = **280 planned requests**. Repeat rounds reuse the same
70 unique reports; they do not increase the independent sample size. Alternate
prompt order by report index and round. Keep every output and failure, and stop
on service/configuration failures without selective retries. Record actual token
usage; this is a small bounded API experiment using the already configured key.

Freeze data, references, prompts, review records, protocol, runtime, and runner
hashes before any inference. The inference phase reads source reports and sends
only patient text to the model. A separate scoring phase reads the references.
Save results under `results/scope-evidence-v3/`; never overwrite previous results.

## Measures, review, and decision

Primary measures are known count-scope agreement, targeted candidate count/scope
checks, and failures caused by unsupported or nonliteral evidence. Inspect
paired cases rather than only pooled averages. Report completion, matched
observations, known counts, known dates, assertions, unknown-field overfill,
severity, and issue detection as guardrails. Literal `time_text` boundary
differences remain diagnostics, not automatic semantic regressions. Evidence
matching ambiguity must be explained where it affects scores.

Compare each round separately. Candidate v3 may become the default only if it
improves the targeted known failures, its fresh-validation count-scope agreement
and completion are no worse in either round, and paired review finds no new
material semantic or evidence failure relative to v1 in either split/round.
Changes only in valid excerpt boundaries or observation IDs are not material.
Do not discard failures, change labels, or tune the prompt after results arrive
to satisfy this gate. If the gate fails, keep v1 and document useful gains and
remaining failures. This conservative adoption decision is not a claim that v1
is error-free or that v3 has no useful improvements.

Any new cases inspected for subsequent tuning become known regression examples.
A later independent claim then requires another frozen validation set.
