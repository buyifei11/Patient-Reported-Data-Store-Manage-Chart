# Temporal prompt experiment: frozen protocol

Protocol date: 2026-11-15. This is prompt engineering, not fine-tuning. The task and normalized schema remain v0.2.

## Question and intervention

Does clarifying relative-day anchors improve date extraction without degrading symptom assertions, counts, or treatment of unknown information?

The baseline is the exact original prompt, preserved as `prompts/extraction_v1.txt`. The candidate is `prompts/extraction_v2.txt`. Only the `day_reference` instruction changes: direct current-report expressions such as `tonight` are explicitly anchored to today; day interpretation is independent of whether a symptom is actual or hypothetical; an unanchored meal or historical narration must not be forced into today. No worked examples or reference answers are added. The three previously observed `time_text` excerpt-boundary differences are not optimization targets.

The revised prompt was written and frozen before the primary implementer inspected the new held-out text or labels. A separate author created held-out cases without reading the revision, development cases, or inference outputs. Independent pre-inference review may correct reference-label mistakes; it must not tune the prompt to the held-out cases. All dataset and code hashes are frozen before any comparison call.

## Data roles

- Original development set: 10 reports, unchanged.
- Additional development set: 20 reports, D001-D020, with separately authored references.
- Held-out set: 20 reports, H001-H020, with separately authored references, kept out of prompts and development tuning.

Both new sets cover time anchors, absence, hypothetical statements, unknown values, incompatible ratings, multiple symptoms, and source reconciliation. These phenomena can overlap across sets; shared patient stories and mechanical rewrites of a case must not cross the split. Case manifests record scenario groups and why each case was included. References are authored from the contract, not generated by the normalization code or copied from model predictions. They are AI-assisted synthetic labels reviewed by another agent, not independently clinician-annotated ground truth.

The additional data are diagnostic examples, not the planned four-week longitudinal dataset. The 20-case held-out set is small and intentionally enriched for edge cases, so its scores cannot estimate real patient-population accuracy.

## Controlled comparison

- Model: `gpt-5.4-mini-2026-03-17` for every call.
- Same candidate schema, deterministic normalization, evaluator, reasoning effort `none`, 2,048 output-token cap, and request settings for both prompts.
- One attempt per report and prompt on the combined 30-report development set: 60 requests.
- Two paired rounds on the same 20 held-out reports: 80 requests. These repeats assess variability; they do not increase the independent sample size.
- Alternate which prompt runs first by report and round. No automatic retries or selective replacement of unsuccessful answers.
- Save actual candidates and normalized results before scoring them. Preserve previous results. Reference data never enter the model request.
- Record prompt, source, reference, runtime-code, and runner hashes alongside requested/returned model IDs, token usage, timing, and failures.

Total planned requests: 140. With usage similar to the first run, the listed-price cost is expected to remain well below $1; exact usage will be reported, not assumed. Service/configuration failures stop the experiment and remain visible. No model requests are made by offline tests or artifact rescoring.

## Measures and interpretation

The primary measure is known-date agreement, with its numerator and denominator. Also inspect `day_reference` checks on text candidates where provided. A post-normalization date score includes code and questionnaire reconciliation, so it is not a pure LLM extraction metric.

Guardrails are report completion, observation precision/recall, assertion accuracy, known-count accuracy, and unsupported filling of reference-null fields. Report severity and issue detection as secondary outcomes. Keep exact `time_text` matching as a diagnostic; do not treat a wider, equally valid source excerpt as a different clinical event.

Evaluate each held-out round separately and inspect paired per-report improvements and regressions. A higher pooled score alone is insufficient to declare a universal improvement. No statistical superiority or clinical-readiness claim is planned.

The candidate can become the default if it improves the observed temporal problem and the held-out comparison shows no material regression on the guardrails across both rounds. Otherwise retain the baseline as the default and report the tradeoff. No further prompt or label tuning is allowed after viewing held-out model outputs in this experiment. If those outputs guide later changes, these cases become known regression cases and a new held-out set is needed.
